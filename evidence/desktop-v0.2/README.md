# v0.2 桌面工程预览验证

范围：实际桌面软件、合成 Runtime、SQLite 告警、协议适配与错误处理。未获得 Windows 目标机访问；Seetong 实景、4060 十路吞吐、准确率和长期稳定性仍为 NOT_TESTED。

演示是运行中的 Qt 自有控件画面录制，不是操作系统读屏。全程合成输入、脚本按钮操作，没有调用视觉模型。主视频实际解码 1045 帧、130.625 秒；10 段合成证据各解码 181 帧、90.5 秒；内置播放器实际播放 24 帧；重建窗口后待办 7→7，内容集合一致。

原生 ScreenCaptureKit 录制试验失败：两种窗口过滤与运行循环对照仍只有 4 帧。一个失败文件容器标称 15.455 秒，实际视频只有 4 个样本；因此不能仅检查时长。代码新增样本数和时长联合拒绝条件，失败文件读回已被拒绝。此结果不证明原生采集已修复。

独立审查问题与修复：

- 25 条完成事件重启：修复 GUI 只保留 20 条显示缓存引起的 KeyError。
- 接口总截止时间：覆盖分阶段慢响应；超时不代表正常，也不盲目切换备用。
- 慢请求接收：有界接收期限，释放唯一接收槽。
- Windows CI：每个命令独立步骤，测试失败不能被后续命令成功覆盖。
- 权重路径：明确绝对路径，提供 CLI 覆盖且不回写已有配置。
- 桌面入口拒绝 live + display，防止本程序自身窗口污染输入；冻结核心诊断入口保留。回放期间隐藏弹窗，候选继续保存。
- 设备页面曾在 UI 线程重复探测 GPU，现改为读取后台缓存；回归测试禁止 UI 调用 GPU 子进程。
- 首轮 Windows CI 的两个繁忙响应测试出现 TCP reset（106 通过、2 失败；同轮 Mac 通过）。拒绝路径原来在未读请求时直接关闭连接，现采用有界拒绝线程、写半关闭和有界 drain，避免丢失 429 响应。保留原失败断言并补连接释放/并发上限回归；最终 Windows 结果见 Release 对应的新 CI 记录。[连接关闭原理](https://learn.microsoft.com/en-us/windows/win32/winsock/graceful-shutdown-linger-options-and-socket-closure-2)。
- 第二轮 Windows 已通过正常请求的完整 429 断言；剩余一项针对故意不完整上传的关闭测试只接受 EOF，未接受 Winsock 的连接中止。该断言现仅同时接受 EOF/连接重置/连接中止，仍拒绝超时；0.3 秒接收截止、429 正常响应和后续 200 恢复检查保持不变。

8GB 是保守基线，硬件升级不自动增加负载。本版新增单卡资源采样、5 GiB 使用/3 GiB 空闲准入、超过 6 GiB 停发复核、固定预热模型核验、输入缩放和禁止绕过网关的入口。缺失 GPU 的本机实际拒绝报告见 [8GB 预热拒绝](8gb-no-gpu-refusal.json)：没有发起加载或下载。该报告是预期的保护拒绝，不是 8GB 实机性能测试。
