# 桌面告警与设备适配设计

## 目的与本轮范围

用户授权自主选择产品形态、架构与执行方法。目标是把现有监控核心变成可操作、可解释、可复查的桌面软件；优先 Seetong 窗口/屏幕输入，中国大陆本地运行，设备以 RTX 4060 或约万元整机作为待测基线。本轮交付桌面扩展、异常候选弹窗、人工处理持久化、两种本地模型协议及硬件建议、可复现演示和升级方案。现场 Windows 不可远程访问，因此不宣称现场行为准确率、真实十路吞吐或 72 小时稳定性通过。

## 产品选择

选择 Windows 优先、Mac 可运行的桌面软件。沿用 Python 3.12/PySide6 与本地 SQLite，不另建浏览器插件、云端平台或新的摄像头平台。浏览器插件无法覆盖 Seetong 原生窗口；纯云方案增加画面出站和网络依赖。内部适配器可替换，用户仍只操作一个工作台。

冻结的 `implementation/` 保留为可回退核心；新代码放在 `desktop/src/factory_monitor_desktop/`。扩展复用核心公开的 GUI 事件方法、运行控制器和事件库，不复制检测/录像代码，不 monkey-patch 核心，不改旧资源包或 Windows 现场副本。新版本源码包同时包含核心与桌面扩展。

## 告警闭环

`RuntimeController` 候选/分析更新 → `DesktopWindow.upsert_event` → `AlertInbox` → 一个非模态弹窗 → 查看证据/已阅/人工确认/误报/稍后处理。模型尚未完成时立即显示候选；超时、错误、证据不足仍要求人工复核，不伪装为正常。

`AlertInbox(path)` 以独立 SQLite 保存事件快照、首次到达时间和处理记录。接口：`observe(event, now) -> bool`；`pending(now, limit=100) -> list[dict]`；`resolve(event_id, action, now)`；`snooze(event_id, until)`；`get(event_id)`；`close()`。相同 ID 重放不增加待办，终态模型变化更新原候选；已处理事件不会因迟到模型消息复活。人工标签先写核心事件库成功，再关闭待办。关闭弹窗不删除事件。积压以数字和列表显示，不堆叠十个抢焦点窗口。

每次最多显示一个非模态窗；声音有冷却，模型更新不重复鸣叫。所有动态文本按纯文本显示；证据路径只能打开当前数据目录中的已存在文件，拒绝越界和符号链接逃逸。退出停止计时器并关闭存储，不改变原运行时停止语义。

**采集反馈约束**：live 使用 display 捕获时禁止浮层和系统气泡，以免告警进入被分析画面。live 窗口捕获须有已校准的非本软件窗口名；运行时无明确可排除浮层的窗口路径时同样抑制弹窗，显示原因并保留待办。窗口捕获仍需现场遮挡验证。demo/video 可展示弹窗，但显著标记输入性质。

## 模型适配与设备建议

`ModelRouter` 支持本地 Ollama 与本地 OpenAI-compatible 视觉服务，两种实际协议经 HTTP 假服务测试。默认只允许回环地址、忽略代理、禁止重定向，不配置付费云调用或生产画面上传。模型要求 vision + 多图 + 结构化输出，不能用文本模型替代视觉模型。

路由参数包含协议、端点、固定模型名、最大图片数、单次时间预算、最大并发和候补模型。主模型不可用时，在同一总截止时间内至多尝试一个备用；429/队列已满与超时明确返回未完成。校验结构化结果和可见证据，不把无效结果当成 supported。输出保留实际模型、尝试次数、失败原因和耗时。并发上限初始为 1，设备型号不直接授权更大并发。

通过独立回环 `ReviewGateway` 提供核心已有的 Ollama `/api/chat` 协议，从而不用改冻结核心。桌面启动时可显式选择路由配置；没有配置时仍保持原核心配置，demo 默认关闭模型。自检/硬件建议只产生建议，不自动安装软件、下载模型或覆盖现场配置。

硬件探测记录操作系统、内存、可用 NVIDIA 显存（探测失败标未知）与 Apple 芯片情况。提供 CPU 保底、Apple Silicon、NVIDIA 8 GB、NVIDIA 12–16 GB、24 GB/多机等建议；每档给出限制和升级触发条件，所有吞吐字段 `NOT_BENCHMARKED`。先测采集、检测、视觉编码、排队、推理、证据保存分别耗时，再判断显存升级、模型量化、关键帧减少或异构任务分工。暂不实现大模型跨卡拆分。

## 展示和验收

本轮演示须运行实际桌面程序并录制其窗口；合成输入、脚本注入和真实模型调用各自标注。展示候选到达、并发积压、逐项处理、证据查看、故障、重启恢复。不能用界面动画冒充检测、不能用合成行为冒充摄像头现场。

当前 Mac 可录制软件演示。最终现场交付以目标 Windows 的实际 Seetong 运行和同步录屏为准：1→3→10 路、15–30 分钟可操作演示、100 次切换及 72 小时长测；性能、准确率、掉帧和模型积压同时记录。录像是证据，实机运行才是验收对象。

## 主要失败模式

断流/窗口变化应保留盲区状态；模型拒绝、超时、无效 JSON 不得悄悄降级为成功；告警风暴不得阻塞采集；已确认事件不因重启重报；无证据不能显示已播放；摄像头细节太小时必须标为不可判读。任何一次版本更新都能退回 v0.1.0-preview。
