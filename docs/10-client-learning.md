# 现场客户端学习与适配

本章定义怎样为**一个明确的软件版本和显示状态**采集可复核的适配证据。它是现场操作规程，不表示适配器或自动点击已经交付。当前主动观察实验仍是离线隔离实验；目标 Windows 电脑没有远程访问条件，实际 Seetong 版本、DPI 坐标、十路行为、码流切换与识别准确率均未在本现场验证。自动 OS 点击仍 disabled。历史 Seetong 安装包预检只核对过候选文件的格式与哈希一致性，不能证明本现场客户端来源、安装、安全性或兼容性，详见[Seetong 文件与平台预检](../implementation/docs/SEETONG_CLIENT_PREFLIGHT_zh.md)。

本仓库提供[软件适配采集模板](../templates/software-adaptation.template.json)，模板从 `not_tested` 开始，不含操作者姓名、摄像头账号、现场地址或生产画面。填写副本时保存在现场受控目录；只将经过脱敏的结构和结论纳入版本管理。原始截图、窗口录像、客户端配置、用户名、设备序列号、认证信息和生产模型数据留在获准现场存储中。模板是人工记录格式，不是当前 runtime 自动加载的适配配置。

## 已确认的首个适配方向：Seetong 屏幕优先

用户已确认优先使用 Seetong，主要读取电脑屏幕画面。首轮工作以原生屏幕/窗口采集、逐路裁剪、画面身份和新鲜度检查为基础，不把 SDK、RTSP、账号接口或监控软件的扩展能力作为必需前提。具体 Seetong 版本、DPI、宫格和通道顺序仍需现场读取。可从[Seetong 屏幕适配记录](../templates/seetong-screen-first.template.json)建立本地副本。

捕获层面尽量通用：屏幕上可以显示单个或多个客户端；每个有效区域必须有独立的通道身份和状态。操作层面按视觉示教学习“进入详情—读回身份和新帧—返回总览”，不能因软件换名就套用旧坐标。首版仍由人工切换，受控点击实现与验收尚未完成。若不需要操作客户端，持续屏幕读取不依赖自动点击。

通用屏幕输入解决的是接口依赖，不能恢复画面没有显示的细节。遮挡、最小化、黑屏、锁屏、冻结帧或小宫格里无法辨别的手部/小物件要标为不可观测；放大也必须证明实际取得更多源信息。不能把“能截屏”登记为“所有软件和画面都可准确分析”。

## 适配包识别范围

一次适配只对下面组合有效：监控软件名称与精确版本/构建号、操作系统版本、捕获后端、窗口标题和窗口指纹、捕获像素尺寸、DPI 缩放、窗口位置/尺寸、客户端布局、通道顺序、语言/主题、主子码流状态以及校准 ROI。改变其中任何一项都创建新适配包并重新验证，不能覆盖旧记录，也不能把一台电脑的坐标直接复制到另一台电脑。

窗口指纹应由可审计的非个人属性组成，例如进程文件产品版本、精确窗口标题、窗口客户区宽高、布局状态、固定 UI 锚点/控件属性、捕获后端和校准截图摘要。不要把登录名、账号、设备地址或易变的绝对窗口坐标当作唯一身份。截图摘要只用于发现本地文件变化；它不证明来源或真实性。若客户端不提供稳定控件属性，记录这一限制并要求每次人工复核，禁止把临时坐标伪装成稳固指纹。

模板中 `profile_id`、`fingerprint_sha256` 和摘要值须在收集后计算并写入；未实际计算时保留空值。`record_schema_version` 是此记录模板版本，不等同 `inspection_profile` 回放契约中的 `schema_version`。本模板没有通过 GUI 或 runtime 导入的能力。

## 现场采集顺序

### 1. 准备与隔离

1. 由现场负责人确认可读取客户端、目标摄像头和测试时段；由有权限的值班人员自行登录。不得将凭据交给操作人员记录表、代码仓库或模型提示词。
2. 在 Windows 目标机上记录应用名、完整版本号、安装来源/签名核验结果、OS 版本、GPU 与驱动、Python 3.12 环境、屏幕物理像素分辨率、显示缩放百分比、客户端窗口客户区大小、窗口标题、布局与通道顺序。Windows 是优先验证路线。
3. macOS 只作为单独适配目标。先确认获准客户端确实支持该 macOS 版本；ScreenCaptureKit 采集需由操作者授予屏幕录制权限，检查窗口遮挡、最小化、切换用户/锁屏和重新授权恢复。Windows 二进制、CUDA wheel 和 Windows 配置不可移植为 Mac 运行环境。SCK 权限存在或能截到画面不代表客户端/十路性能已通过。
4. 使用新的适配 `profile_id` 和新的本地证据目录。原始采集仅在现场受控路径保存；给每张截图/短录像记录时间、客户端状态、所对应 camera ID、窗口状态和 SHA-256。校准后再次读取文件并核对摘要。
5. 手动验证全部通道在原客户端能播放。按[客户端校准步骤](04-client-calibration.md)标 ROI 和身份；网格身份键集合必须恰好匹配当前启用摄像头。每路独立心跳需来自该路源端时钟、序号或现场证明的播放指示。首帧保持未知，其他相机或桌面时钟不能替它背书。

若应用版本、窗口大小、布局或 DPI 发生改变，停止当前采集，标记旧包 `stale`，在新目录重新建档。旧包作为回滚基准保留。

### 2. 一次人工示教

示教由操作者亲自操作客户端一次，并逐帧记账；示教只提出候选状态和动作，不会生成已获许可的自动控制。对于每种布局分别执行并记录：

1. **总览稳定态**：显示网格，记录窗口指纹、所有可见 camera ID、布局指纹、每路最新心跳和截图帧时间。
2. **进入详情**：操作者手动选择已确认 camera ID；在动作前记录 request/cycle ID、目标 ID、当前视图与时间。观察客户端真实行为，判断是单独详情窗、当前窗换布局还是仅视觉放大。
3. **新帧身份确认**：动作后等待晚于请求时刻的新捕获帧；读出详情标签、详情布局唯一标记、目标源心跳、capture timestamp、ROI 变换和源分辨率/主子码流状态。只匹配文字标签但帧时间不更新，仍为未知。
4. **返回总览**：操作者手动返回，等待请求之后的新网格帧；核对总览指纹、完整 camera ID 顺序、逐路心跳恢复和盲区结束时间。写下用时及失败点。
5. 重复采集第二次只用于验证步骤是否可复现，不意味着可以无监督点击。若一次示教中出现弹窗、失焦、布局变化、遮挡、锁屏、错 ID 或过期帧，停止并保留失败记录；不要把失败尝试删掉后只留成功样本。

放大是否提高信息量必须单独证实：读取客户端主/子码流状态页、该详情视图的源分辨率和帧率，或经授权且有可靠来源信息的码流元数据，并在相同场景/时间对照网格。可辨细节确实来自更高分辨率源帧才记录“切到高清/主码流”。单纯控件变大、插值后像素变多、ROI 放大、锐化或模型置信度提高都不算源信息增加。若无法读取码流信息，记 `unknown`，不宣称放大切换了高清；同时记录此时其余镜头不可见的盲时。

### 3. 心跳与无人物目标变化

对每路分别保存网格、详情可用的 heartbeat 来源与 ROI、采样间隔、观察时长、冻结阈值、首帧状态和恢复证据。ROI 使用 0–1 归一化比例，分别相对该路裁剪图或完整详情帧；不要把不同截图的像素坐标混用。`camera_heartbeats`、`grid_identities` 与 `detail_identities` 目前可由 runtime 消费手工配置，详见[实时校准契约](../implementation/docs/LIVE_CALIBRATION.md)。实际阈值仍须用目标客户端证据校准。手工回执/模板存在不等于客户端窗口被可靠识别。

目标变化候选不应依赖“画面里有人”：应包含无人物时物件/工件/料箱变化、遮挡/移入移出、画质异常和定时覆盖触发。像素变化只可产生“此区域发生变化”的候选，不能直接判定物体身份、员工行为、原因或意图。静态场景、阴影、灯光变化、镜头抖动、压缩变化也要作为负例。若该阶段运行的软件仍没有接入无人物变化检测，记录为未实现，不以人工观察结果填成机器能力。

### 4. 建立确定性状态机候选

根据示教记录写出有限状态机表，不让视觉模型在运行时自由探索界面。每一步有明确的前态、守卫条件、人工/将来受控动作、等待期限、预期后态、新鲜回执、成功条件、失败状态和恢复动作。建议状态及约束如下：

|状态|进入条件|允许动作/判据|失败时处理|
|---|---|---|---|
|`grid_verified`|新鲜网格帧；布局指纹匹配；启用 ID 与身份映射完全一致；每路心跳独立通过|仅可提出指定 camera ID 的详情请求|保持总览；任何身份歧义转 `unknown`|
|`detail_pending`|新请求 ID、目标 ID 和前态快照已记录|等待晚于请求的新帧；不重复发动作|超时、焦点丢失、弹窗或版本指纹变化转 `fault`|
|`detail_verified`|详情标签与唯一详情布局标记匹配；相机身份、时间戳、目标路 heartbeat、ROI 和质量都通过|在配置的最长驻留时间内复核；其它路标盲|标签、心跳或画质任一失败转 `unknown` 并要求人工回总览|
|`grid_return_pending`|返回请求与动作前详情快照已记录|等待晚于请求的新网格帧与布局 readback|超时或客户端失焦转 `fault`，停止后续轮询|
|`fault` / `unknown`|任何身份不符、旧帧、心跳冻结、弹窗、锁屏、遮挡失效或超预算|禁止继续动作；人工确认窗口并恢复总览，重新取得新鲜证据|保留日志/媒体、故障原因和不完整周期；未验证恢复不得回 `grid_verified`|

当前隔离实验 `inspection_profile` 的回放审计只检查记录及相应一致性条件，尚未接入 runtime；`inspection_profile` 要求的请求/详情帧/返回请求/网格帧时间顺序、profile 指纹、camera ID、目标守卫、cycle 唯一性和逐路周期数，可作为证据记录质量的检查契约。它不读取真实 UI、屏幕或 OS 动作，不证明按钮可点，也不授权控制；合成记录只叫合成记录。相关实现边界见[主动观察架构](../implementation/docs/ACTIVE_OBSERVATION_ARCHITECTURE_20260925_zh.md)、[实验核验](../implementation/docs/ACTIVE_OBSERVATION_VERIFICATION_20260925_zh.md)和[回放审计模块](../implementation/src/factory_monitor/inspection_profile.py)。

## 验证门槛

先冻结任务、事件定义和数据来源，再调参数。训练样本与验证样本必须按日期/班次/相机/事件片段分组隔离，不能把同一连续视频的相邻帧分到两边；尽量再留一份只供最终验收的锁定集。样本及分割清单记录摘要和标签依据，生产画面不离开现场。验证集只用于一次冻结配置的评估；反复据此改参数后它已成为开发数据，必须新收未见数据做最终门禁。

不同调节方式不能混为“模型学习”：

|改变类型|所需证据与门槛|不能据此声称|
|---|---|---|
|规则阈值/最小变化量/冷却时间|先以独立训练集选值；在隔离验证集报告按相机与班次拆分的召回、误报、UNKNOWN、延迟和负载。至少覆盖阴影、光照、反光、遮挡、镜头震动、视频冻结、空场及无人物物件变化；冻结阈值前登记可接受误报和漏报预算|只因样本内“看起来更稳”便宣称准确率提升|
|ROI/身份/画质模板|模板取自目标版本与固定窗口状态；对相同标签、相似布局、重排通道、分辨率/DPI变化、低清、压缩和弹窗做留出误匹配检查。每个启用 ID 唯一对应；误匹配应拒绝而不是选次优|模板通过表示身份可信或 UI 点击安全|
|提示词/复核说明|冻结本地模型、版本、提示词和输入预处理；对独立正负样本盲评事实准确性、无依据陈述、UNKNOWN、延迟和人审一致性；版本任一变化需完整重评|提示词验证等于模型训练，或可判断动机/违规事实|
|权重微调/蒸馏|须有授权训练数据、来源与标签审核、独立训练/验证/最终测试集、可复现配置与权重摘要、模型卡/许可审查、回滚副本、现场验收门禁；先离线小样本验证再申请部署审查|有一个微调权重就完成现场学习、解决码流/遮挡/DPI，或准确率已达标|

阈值不能在锁定验收集上反复调优；每种任务（大件移动、小物件变化、手部动作、工位占用、画质异常）各自设样本和门槛。一个任务过关不外推到别的任务/相机/分辨率。通过报告至少列出 TP/FP/FN/UNKNOWN、误报暴露/小时、按路覆盖率、处理延迟分位数、队列丢弃与人工复核结果，并给证据清单摘要。低质量输入必须成为 UNKNOWN 或无法观察，不能作为模型阴性。

## 阶段放行、故障恢复与回滚

|门|放行条件|失败动作|
|---|---|---|
|A 环境识别|客户端版本、OS、DPI、像素尺寸、窗口指纹、布局、通道表和捕获权限均有现场读回|不采集控制样本；修复权限或新建 profile|
|B 图像与身份|每路唯一身份；网格/详情样本独立；心跳与新鲜帧均按路验证|该路标不可观测；禁止模型把它当作正常样本|
|C 人工闭环|人工示教 detail→grid 的 request ID、新鲜帧、身份、布局与回返记录闭合；记录放大来源证据和盲时|人工接管；不进入自动控制开发门|
|D 确定性回放|隔离记录无重复 ID、无重叠/倒序周期、时间顺序满足契约；所有坏记录计失败|保留失败证据、修正后新建 profile，不覆盖旧结果|
|E 任务验证|按具体任务完成训练/验证隔离和误报、召回、UNKNOWN、延迟门槛|保持提示/建议级；未达标任务关闭或明确标未知|
|F 现场长期验收|经独立安全审查后，在目标机进行有监督故障注入、长时运行、恢复与人工处置；窗口控制仍须独立实现及审批|停止现场试验并退回人工客户端操作|

当前最多能据已存在工具做静态本地校准与实验回放；它们不具备自动操作客户端的生产路径。自动 OS 点击 disabled。即便未来新增受控适配器，也须在独立审批和目标机验证前由人工执行示教动作。

遇到客户端升级、DPI/分辨率变化、窗口重建、布局/通道重排、辅助弹窗、登录过期、锁屏、焦点或采集权限变化：立即停止本轮，冻结 profile，保留完整失败日志、截图索引和尚未排空的数据目录；不能删除失败记录来“重跑变绿”。创建新 profile 与新目录，从 A 门重来。回滚时明确恢复上一个已通过身份/心跳验证的版本及其配置副本；旧版数据与新版失败数据分开保留，确认进程停止、输出读完后才归档。窗口坐标或模板不匹配时清除其可用状态并回到人工模式，禁止沿用旧坐标盲点。

正式门禁必须做遮挡、最小化、锁屏、弹窗、失焦、切换用户、窗口移动、分辨率/DPI 改变、视频冻结、断流重连和软件重启测试；每种状态下都证明旧帧不会被当成新帧、错 ID 会 fail closed，且恢复后重新完成身份和逐路心跳验证。点击周期与样本数量按[验收协议](../implementation/docs/ACCEPTANCE.md)及目标现场另行登记。本章不把尚未执行的次数或准确率写成已完成结果。

## 模型文件存放

模型权重以同一私有仓库的 Release 实体附件交付，源码 Git 历史保留模型版本、来源、许可与哈希清单。完整 Windows 资源 ZIP 含通用 Qwen 和 YOLO 权重，按[全量下载与还原](09-delivery-and-offline.md)取得并核验；不是只有下载链接或空指针。生产训练数据与现场截图仍留在获准存储，不随模型上传。后续软件适配或模型微调产生新权重时，必须绑定数据集版本、独立测试结果与新哈希，另建版本，不能替换当前固定包后沿用旧验收。

当前实时检测需现场已有并已校验的 `models/yolo11n.pt`；缺少权重会使 live 检测无法启动。Qwen/Ollama 只是可选的本地语义复核路径，不能替代 YOLO 实时检测，也不能替代人工确认。Windows 离线候选中已有的权重可按授权与 SHA-256 核实后单独复制到合规现场位置；同仓 Release 可取得已登记的完整分片和模型；不要复用 Windows 二进制或 CUDA wheels 到 macOS。Mac 需使用获准的相同权重文件并独立核验兼容性与来源；本章不提供未核实下载 URL。
