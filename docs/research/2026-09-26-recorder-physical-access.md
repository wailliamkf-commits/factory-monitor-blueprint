# NVR 接口与现场接线预案

日期：2026-09-26

用途：让现场安装师傅协助确认“一台录像机、一路视频、Windows 测试电脑”的只读接入条件。当前录像机/摄像机品牌和完整型号未确认；本文是预案，不代表设备已支持接口或网络已连通。

## 先确认录像机，再谈地址

第一优先是 **NVR/DVR 的品牌、完整型号和固件版本**，不是先把每台摄像机型号全部收齐。请师傅拍一张录像机背面/底部铭牌和背板接口照片；如设备菜单可见，再拍“系统信息/版本信息”。完整型号常在机身铭牌、包装标签、设备信息页或原安装单上。照片请避开序列号、二维码、账号和口令，或者先遮住这些内容。摄像机型号及九路通道对应关系之后再补。

对天视通（Seetong），本次查到的官方在线帮助给出的是**天视通摄像机** RTSP 地址示例，并描述“在录像机视频管理中添加摄像机”；这说明录像机作为客户端去取摄像机的流，不能证明录像机自身会向外提供逐通道 RTSP。另一个天视通帮助页面说明 NVR 可配置接入 GB/28181 平台，参数由平台提供；这也不是对外 RTSP 地址说明。[天视通：录像机 RTSP 取摄像头](https://help.seetong.com/fqa/question/3874/1905458) [天视通：NVR 接入 GB/28181](https://help.seetong.com/fqa/question/3874/1904378)。目前结论是“天视通 NVR 对外 RTSP 能力和对应型号路径未确认”，不能据此说一定支持或一定不支持。

## 电脑怎样接入

1. 不拔现有线，先拍录像机背板。认清标为 **LAN/Network/网口** 的上联网口，以及标为 **PoE/IPC/Camera** 的摄像机口。若只看到 HDMI/VGA，那是接显示器的视频输出口，不是接入局域网的网口。
2. 请师傅指出 NVR 的 LAN 上联网线接到哪台交换机。经现场 IT/师傅安排，把 Windows 测试电脑的网线插到**同一台交换机上预留的普通 LAN 口**，并确认电脑和 NVR 位于同一可互通网段/VLAN，或已有明确路由与访问许可。链路灯亮只说明物理连线，不等于已可访问视频。
3. 如果这台 NVR 有内置 PoE 口，先把它当作专供摄像机的口处理，**不要把测试电脑插进随机 PoE/IPC 口**。例如，海康威视部分带 PoE/内置交换机的特定 NVR 型号有单独的“internal NIC”供接在这些口上的摄像机使用；这是品牌和型号相关的设计示例，不能套用到当前未知设备。[海康威视手册：特定 NVR 的内置网卡与 PoE 摄像机网络](https://www.hikvision.com/content/dam/hikvision/products/S000000001/S000000002/S000000007/S000000032/OFR000061/M000000629/User_Manual/Baseline_User-Manual-of-Network-Video-Recorder_71-E-M_V3.4.90_20180124.pdf)。大华手册也把 PoE 口定义为给网络摄像机供电的内置交换口，并把 Network port 单独列出。[大华 NVR 用户手册示例](https://material.dahuasecurity.com/uploads/soft/20240408/Dahua-Network-Video-Recorder_Users-Manual_V2.3.6-Eng10.pdf)。
4. 先只记录 Windows 当前的有线 IP、NVR LAN IP 和端口，由师傅/IT 确认连通性；测试电脑保持“自动获取 IP”或采用 IT 明确给定的临时设置。**不要改 NVR/摄像机生产 IP、默认网关、DHCP、VLAN、录像格式或硬盘，也不要重置/升级设备。** 若现场只能接入 NVR 私有 PoE 网段，暂停并请集成商给出经批准的转发接线方案，不要临时桥接两个网段。

这次只研究接线预案；没有扫描现场网络、登录设备、读取账号或访问任何私有画面。当前在 Mac 上，仅做文档核查；实际物理接线及 Windows 连通性需由现场人员协助完成。

## 问厂家/师傅的五句话

1. **请先拍 NVR/DVR 机身铭牌、背板接口和系统信息页，告诉我品牌、完整型号、固件版本；先确认录像机，摄像机型号可以后补。** 请遮住序列号、二维码及账号口令。
2. **这台准确型号和固件，是否能让局域网电脑直接按通道读取 NVR 输出的实时主/子码流？** 请给该型号官方手册页/开发文档、RTSP/ONVIF服务开关和一条不含真实密码的路径模板；请明确 NVR 是“对外提供视频的设备/服务端”，不是只用 ONVIF 添加摄像机。
3. **NVR 的 LAN/Network 上联网口接在哪台交换机、哪个网段/VLAN？** 请安排 Windows 测试电脑接同一交换机的空闲普通 LAN 口，并由 IT 确认电脑到 NVR 地址及所需端口可达；不改生产网络设置。
4. **这台 NVR 的 PoE/IPC 摄像机口是否属于独立的内部网段？** 若是，普通办公网电脑能否只通过 NVR 的 LAN 口读取各通道？如不能，请给出厂家支持且经 IT 批准的接线/转发办法；不要让我把电脑插入随机 PoE 口。
5. **请先给一路的通道号、只读预览账号权限、主/子码流路径和每路并发限制。** 用户名/密码请现场单独配置或交付，不写进文档、聊天或截图；一路确认后再扩到其余通道。

## 接口选项怎么区分

| 选项 | 要确认的事情 |
|---|---|
| RTSP | 设备直接给一条视频流地址。须确认这是 **NVR 输出**、通道号、主/子流、账号权限及端口；仅有摄像机 RTSP 地址不能代替 NVR 输出。 |
| ONVIF | 标准设备/客户端接口。NVR 能用 ONVIF 搜索并接入摄像机，只证明它可能作为 ONVIF 客户端；要另问它是否以 ONVIF 设备/服务端身份向外提供媒体配置和流 URI。Profile T 的设备媒体服务可返回流 URI并支持 RTSP，但需该型号/固件实际符合并开放此能力。[ONVIF Profile T](https://www.onvif.org/profiles/profile-t/) [ONVIF Profile 说明](https://www.onvif.org/profiles/) |
| 厂商 SDK/私有协议 | 标准流不可用时的备选。索取准确型号对应的官方 SDK/API、支持的 Windows 版本、授权方式和逐通道主/子流示例；“客户端软件能预览”本身不等于提供可供程序读取的接口。 |
| GB/T 28181 | 面向视频监控联网平台的注册/信令接入路径，需要平台侧参数和双方配置；它不是 RTSP URL，也不能仅凭“NVR 支持 28181”推断本地电脑可直接读到流。天视通帮助页还提到部分 16 路机型只有切到 9 路模式才显示 28181 设置；必须按准确型号和固件核对，不能照通用帮助页擅自改生产通道模式。[天视通 NVR 的 GB/28181 配置说明](https://help.seetong.com/fqa/question/3874/1904378) |

## 厂商路径示例（仅对应所列品牌手册）

下面只是格式示例，用于让师傅确认“这类设备是否有官方路径”；**不是当前现场 NVR 的地址、通道号、端口或登录资料**，不可直接拿去连设备。海康威视官方 NVR/DVR 示例中，`1701` 表示第 17 通道主码流，`1902` 表示第 19 通道子码流：[海康威视官方 RTSP 格式说明](https://supportusa.hikvision.com/support/solutions/articles/17000129024-do-you-have-an-example-showing-the-format-for-getting-a-rtsp-stream-from-a-nvr-dvr-)。大华某系列 NVR 手册示例格式为 `rtsp://<用户名>:<密码>@<录像机IP>:<端口>/cam/realmonitor?channel=1&subtype=0`；其中 `subtype=0` 是主码流，改为 `subtype=1` 是子码流：[大华 NVR 用户手册 RTSP 格式](https://www.dahuasecurity.com/asset/upload/product/20180822/Dahua-Network-Video-Recorder_Users-Manual_V4_4_3.pdf)。只有品牌、设备类型、准确型号及固件都对应时，才查该设备自己的手册并由师傅填入真实通道信息。

天视通帮助里的 `/mpeg4` 和 `/mpeg4cif` 是其摄像机示例路径，**不得当作天视通 NVR 的路径**；海康/大华示例也不能移植到天视通或未确认型号。[天视通摄像机 RTSP 示例](https://help.seetong.com/fqa/question/3874/1905458)
