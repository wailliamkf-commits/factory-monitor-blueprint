# 监控客户端校准与现场验证

按具体软件版本建立一次人工示教与适配记录时，继续阅读[现场客户端学习与适配](10-client-learning.md)，并使用[适配采集模板](../templates/software-adaptation.template.json)。

校准是一次有记录的人工测量，不是模型训练、身份保证或验收通过。先在实际目标系统与客户端上完成逐路确认；未通过的摄像头维持不可观测/未知状态。Windows 使用 WGC 是首选现场路线；macOS 仅在有可用且获授权的客户端和 ScreenCaptureKit 环境时做独立验证。两套系统的结果不可互相替代。

## 开始前固定环境

由现场操作员记录日期、操作者、操作系统版本与显示缩放、监控客户端名称/版本、屏幕分辨率、窗口模式、当前宫格布局、每路通道名称、授权方式与实际画面来源。记录应用源码版本/压缩包 SHA-256、Python 3.12 版本、GPU/驱动、配置文件版本和数据目录。不要把密码、访问令牌或生产画面上传给代码代理、代码仓库或外部图像服务。

先在原客户端人工确认各路实时出图。客户端没有显示独立时钟时，用可见的源端刷新指示或经批准的播放状态作为候选心跳来源；场景中人走动、模型提示、电脑系统时钟和“客户端在线”指示都不能单独代表某一路视频在更新。

开始 Factory Monitor 后选 `live`，先确认必需的 `models/yolo11n.pt` 已在项目中且哈希核实；再设置采集后端、精确窗口标题、捕获像素尺寸与布局版本。Windows 用 `wgc`；Mac 用 `screencapturekit` 并预先确认 Screen Recording 权限。只在操作者确实要采整个显示器时选 `display`，并记录同屏其他窗口可能一并进入画面的风险。Windows `auto`/`wgc` 需要窗口标题；不会静默退回整屏。Qwen/Ollama 是可选复核项，缺少时关闭 `review.enabled` 并保留人工复核。

在应用配置区逐行核对十个固定 ID、名称、启用状态和裁剪矩形。实际客户端若只有九宫格且第十路在另一页，记下页面/布局切换及各路可见状态；不得把空白格或重复瓦片映射为第十路。先确认源画面的颜色、比例、黑边、叠字与真实分辨率，再开始 ROI 标定。

## 逐路图像映射与身份模板

对于每个摄像头逐项记录：

1. 在客户端标出通道标签与实际物理镜头/作业区的对应关系，由熟悉现场的操作员独立复核一次。
2. 用应用的裁剪 `x,y,w,h` 将捕获窗口内的瓦片映射到对应 ID。输入值是相对整张捕获窗口的 0–1 归一化比例，不是像素坐标。先量出像素边界，再填写 `x/W,y/H,w/W,h/H`（`W/H` 分别是捕获窗口宽/高）；例如 1920×1080 捕获画面中左上角 480×360 网格瓦片填 `0,0,0.25,0.333333`。按像素测量确认裁剪不越界、不包含相邻摄像头，也不把动态工具栏算入图像区域。
3. 对照画面内固定可见的通道号/名称；布局中每个启用 ID 必须唯一。名称不清、标签缺失或两路对照冲突时标记映射无效，不凭排布顺序猜测。
4. 在停止状态下加载一张保存在本机的校准预览图，使用「本地身份/网格模板」选摄像头 ID、截图类型和固定标签 ROI，点击「从已加载预览图记录本地模板并保存」。标签 ROI 同样用 `x,y,w,h` 的 0–1 归一化值，相对于当前加载的整张截图；网格模板用整张网格截图，详情模板用整张详情截图，不能混用两种截图的坐标。此功能从静态本机图生成 `data/calibration_templates/` 下的模板，并保存身份 ROI 与阈值；它只创建模板，**不会在录入时校验真实窗口读回**。模板状态提示齐全也不表示映射已经验证。
5. 对网格和详情布局分开核对。若实际客户端有详情视图，只有标签和布局指纹都能区分详情页时才记录它；详情模板不是仅有同一相机 ID 标签即可。配置变化后退出应用再重开，读回 `config.json`、模板路径、ID 数量和尺寸，确认捕获标题/尺寸/后端仍与现场一致。

应用可记录网格/详情身份模板，但逐路 heartbeat ROI 与独立详情布局指纹仍须在配置中手工维护；当前 GUI 没有逐路编辑 heartbeat 的完整流程。运行时已经能消费 `switching.verification.camera_heartbeats`、`grid_identities` 和 `detail_identities`，在 live 捕获中检查新鲜度与身份并将失败路标记为不可用/映射无效。字段能被消费不代表操作员已完成现场标定。模板/heartbeat ROI 使用归一化比例：网格身份 ROI 相对整张捕获网格；详情身份 ROI 与布局 ROI 相对整张详情帧；heartbeat 的 `grid_roi` 相对对应相机裁剪图，`detail_roi` 相对详情帧。示例结构和 fail-closed 条件见[高级实时校准契约](../implementation/docs/LIVE_CALIBRATION.md)。`min_score`、`min_margin` 等示例是配置契约，不代表已经替实际客户端完成标定。

## 分路独立心跳与画质可辨性

如实施人员需要补充高级配置，每个启用 camera ID 都须各自配置网格 ROI、详情 ROI、最小像素变化和最大不变秒数。ROI 应覆盖该路稳定刷新的源端时间/序号或经现场证明的播放指示，且不能因其他路动起来而变化。不能使用一块全局时钟同时为十路背书。首帧属于未知，只有其自己的心跳变化后才可记为可观测；达到冻结期限只让对应一路不可用。

每个布局都记录捕获帧宽高、瓦片有效像素、标签可读性、遮挡/反光/模糊、压缩伪影、画面更新时间及重连行为。对现场任务定义最小可辨物体像素尺寸和遮挡条件。宫格变大或模型换大不能补回源画面已丢失的细节；如果任务需要的小件/手部动作在源图里不可辨，标为不适用/未知，并停止就该任务作准确率判断。

如客户端提供主码流/子码流信息，分别记录宫格与放大后的源分辨率、帧率、码率或客户端状态页；如果没有可见信息，就注明未知。显示窗口放大只证明布局变大，不证明底层码流切到主码流或拿到了新增细节。RTSP/SDK 是未来获授权后的独立入口，当前校准不假设其存在，也不要求更换摄像头。

## 1 → 3 → 10 路手工验证

每一级使用独立配置副本和独立 `data-dir`。先在全十路配置中完成校准并读回，然后将其另存为 master（Windows 可用 `Copy-Item .\config.json .\config-master.json`；Mac 可用 `cp config.json config-master.json`），保留完整配置与十路模板作为基准。不能只在同一份配置里取消未测摄像头的启用状态：运行时要求 `grid_identities` 和 `detail_identities` 的 key 集合与当前启用 ID 完全一致，额外身份条目也会令整幅映射无效；`camera_heartbeats` 也要按当前启用集合核对。每个阶段在副本中只保留当前启用 ID 对应的心跳、网格身份及详情身份条目，再逐项读回核对。GUI 的配置面板可编辑启用状态并保存，但高级 `switching.verification` 需在副本 JSON 中手工维护；不要修改 master 文件。创建副本前先确认目标运行目录不存在；失败或重复运行时保留原阶段目录，另选新目录。

Windows 从 `implementation/` 目录为每阶段建立独立路径、复制 master 配置后，使用项目现有 GUI CLI 参数启动（这些参数会加载该副本并把输出写入对应数据目录）：

```powershell
if (Test-Path .\runs\stage-1) { throw 'runs\stage-1 already exists; preserve it and choose a new stage directory.' }
New-Item -ItemType Directory -Force .\runs\stage-1 | Out-Null
Copy-Item .\config-master.json .\runs\stage-1\config.json
New-Item -ItemType Directory -Force .\runs\stage-1\data | Out-Null
.\.venv\Scripts\python.exe -m factory_monitor gui --config .\runs\stage-1\config.json --data-dir .\runs\stage-1\data --source live
```

在离线候选的副本上直接用其项目解释器时，先从候选包根目录设置 `YOLO_OFFLINE=true` 和 `YOLO_CONFIG_DIR=<候选目录>\runtime\yolo-settings`，再将该候选 `.venv\Scripts\python.exe` 与相同 CLI 参数组合；候选配置中的检测权重路径应仍指向包内已校验权重。

Mac 在 `implementation/` 中以同样方式复制配置和 `data/`，调用真实 CLI 参数：

```sh
test ! -e runs/stage-1 || { printf '%s\n' 'runs/stage-1 already exists; preserve it and choose a new stage directory.'; exit 1; }
mkdir -p runs/stage-1/data
cp config-master.json runs/stage-1/config.json
.venv/bin/python -m factory_monitor gui --config runs/stage-1/config.json --data-dir runs/stage-1/data --source live
```

为 stage-3 和 stage-10 使用各自目录和新副本，并在每个副本中核对 `source.calibrated`、捕获尺寸及模板路径。离线候选的 `Run-Candidate.ps1` 固定使用 `runtime/monitor.json` 与 `runtime/data`；分阶段时不要共用它那组固定路径，直接从候选的 `.venv` 运行上述 CLI，将 `--config` 与 `--data-dir` 指向独立阶段目录，并保留候选包所需的 `YOLO_OFFLINE=true` 和 `YOLO_CONFIG_DIR` 环境设置。

每一级在开始前确认上一层证据可读、停止路径可用、磁盘有空间，并开一个独立运行记录。每路记录相机 ID、通道标签、人工镜头确认人、布局版本、启动/停止时刻、可观测秒数、停滞/丢帧/错绑、候选与本地证据引用。超时、UNKNOWN、无画面和错误都保留在分母，不按“没报事件”算作正常。

**1 路：**只启用一个通过标签与心跳初核的摄像头。观察其捕获帧连续变化，人工对照监控客户端切换前后 ID，并检查保存的事件/日志引用仍指向此路。按「停止」确认 worker 结束和输出完成。错误、模糊、冻结或 ID 不一致即停止并修正配置。

**3 路：**启用三台不同的真实镜头，操作员手动轮换客户端视图或保持三路网格。核对每路心跳独立变化、裁剪不串路、某一路停滞时只有该路标为不可用。至少主动观察一次标签不清/遮挡和客户端切换造成的未知状态，不能让其它两路心跳掩盖缺失路。

**10 路：**确认十个唯一 ID、逐路心跳和图像质量条件后才启用。记录同时候选数、队列接受/拒绝/超时、采集缺口、证据录制与停止排空。若切换为详情页，其他屏幕上不可见的摄像头应记录盲区；不能把单屏轮巡称为十路连续实时观察。发生错绑、欠新鲜、磁盘压力或 worker 不能自然停止，立即结束本级，保留日志和不完整状态。

## 人工标定与严谨验收的区别

保存的配置证明本地写入成功；profile receipt 或模板清单证明输入数据可解析；合成样本证明有限逻辑路径。这些都不是实际窗口读回。运行时可以消费手工提供的身份和 heartbeat 校准，但其标签匹配、新鲜度结果、DPI 坐标映射和新帧读回仍需目标客户端证据。本版本的自动 OS 点击、放大和返回保持无条件禁用；配置 `switching.enabled`、录得模板或点 GUI 控件都不能授予桌面控制权。界面中的「返回九宫格/网格」仅可能提出请求，操作员需手动切换后再查看新画面。

放行真实自动控制前，必须先新增并独立验收目标客户端专用 UIA/命中测试或 DPI 安全适配器，然后做 100 次 detail→grid 周期及缩放、失焦、遮挡、弹窗、窗口移动、最小化、重启等故障注入。每次动作要有请求 ID、动作前后视图、capture timestamp 晚于动作时刻、目标镜头身份、布局指纹和恢复结果。任一错 ID、旧帧确认或不能返回即阻断，不能只报总成功百分比。

行为/物料模型另需每类独立冻结的至少 50 个正样本和 100 个负样本，分别评估候选与最终复核的召回、误报、不可判定和含队列时间的延迟。另需正常班次误报暴露、真实 15–30 分钟功能演示、完整班次及 Windows/macOS 各自 72 小时运行证据。当前这些目标系统数据均未齐备；[验收协议](../implementation/docs/ACCEPTANCE.md)给出门槛与记录字段。四个主动观察模块尚未接入 runtime，见[实验核验记录](../implementation/docs/ACTIVE_OBSERVATION_VERIFICATION_20260925_zh.md)。

## 失效处理、停止和回退

- 窗口标题、分辨率、DPI、布局、摄像头顺序或客户端版本变化：停止 live，配置保持未确认，重新采集映射和样本；不要沿用旧身份模板。
- 心跳不独立、首帧冻结、标签匹配不唯一、详情布局不可区分：将该路设为不可观测，保存具体原因，不启动依赖该路的事件结论。
- 捕获权限/后端不可用或窗口遮挡行为异常：停止测试、记录 OS 权限和日志；不得把显示器截图循环包装成 WGC 或 ScreenCaptureKit。
- 停止未排空或进程仍在写数据：不强制重启同一数据目录；先保留进程状态、主库/WAL/SHM、日志和媒体路径，标记不完整，由现场维护人员审阅。

结束当前级别时按应用「停止」，等状态结束后再复制本机运行记录。恢复旧版本时使用新目录、旧配置与其兼容数据副本；保留新版本数据供审阅，不用旧库覆盖新写入。完整的更新/回退边界见[Windows 稳定运行手册](../implementation/docs/STABLE_OPERATION_zh.md)。本章不允许或要求用户对外发送现场资料。
