# 路线图与容量边界

这条路线先建立可信的采集和恢复，再验证语义与容量，最后决定是否扩展硬件。任何规划预算、模块实验或单次性能结果都不构成现场性能承诺。

## 分阶段开发顺序

| 顺序 | 工作 | 放行所需证据 | 未满足时的决定 |
| --- | --- | --- | --- |
| 1. 固化证据身份与人工流程 | 每个候选绑定 `source_id`、`camera_id`、原帧身份/哈希、单调时间、配置/模型身份、缺口和人工复核；保留模型输出与人工结论的分离。 | 本机只读回放与 SQLite/媒体/人工标签能逐事件对账；未知不会显示为正常。 | 不接现场自动行为；只做本地合成或被动单路采集。 |
| 2. 无屏幕合成与故障面 | 补齐显式队列账、资源/磁盘趋势、故障和停止证据；修复证据热路径和自然退出问题。 | 固定负载下，候选/证据/队列/停止可完整对账；媒体逐帧解码；反复故障注入没有静默丢失。 | 不增加镜头数或运行时长来掩盖账目缺失。 |
| 3. 单路实际客户端，被动采集 | 现场逐路识别、capture backend、ROI、缩放、时钟、heartbeat 与来源像素能力；保留手动切换。 | 单路真实采集有本地读取证据，标出盲区；事件时间与源画面能对齐。 | 若输入分辨率/帧率/视场不足，先改善源流或客户端布局，不用超分放大冒充细节。 |
| 4. 十路接入与候选语义 | 完成十路映射、独立 heartbeat、画质故障、ROI/跟踪重置；采集独立标注正负集，按事件类分开检查规则、检测器、VLM。 | 十路身份零错绑；所宣称任务满足样本量、召回、p95、误报率；十候选压力结果包含所有 timeout/unknown/error。 | 候选策略不可靠时停在候选提示与人工复核；不宣称自动判断行为。 |
| 5. 安全接入 Computer Use (CU) | 只在已授权目标客户端以人工确认后的版本化 profile 接入确定性状态机；运行时停止使用模型探索点击。 | 动作闭环每一步校验 request ID、期望相机、view mode、layout fingerprint、frame time 和新帧回执；100 次实际切换和弹窗/失焦/遮挡故障注入均零错绑，回总览可读回。 | 任一坐标不明、layout profile 过期、帧过期/错绑或回总览失败时冻结动作并转人工；禁止盲点或自动重试。 |
| 6. 有界 VLM 和语义 Gate | 在候选形成后复核独立 ROI 与上下文帧；每路有界最新值队列、截止时间、有限输入尺寸、单一模型槽基线、显式人工确认。 | 保持 15 秒队列总 SLA；同时证明困难负例和正例的准确度、延迟分布、显存/内存、取消/OOM/恢复。超时/未知仍记分母。 | 现有 Qwen 2/10 在 15 秒内完成且两个完成项都误报公交负例，当前不满足。先改输入/模型/候选和规则并在独立留出集复测，不以扩容队列或放宽 deadline 取巧。 |
| 7. 演示与长稳验收 | 先真实 15–30 分钟演示，再完整班次与每平台 72 小时运行；逐步加入峰值、断流、磁盘、重启、保留与恢复试验。 | [验证手册](05-validation-and-acceptance.md)中的数据、切换、覆盖、准确率、时延、误报及完整性 Gate 全部通过，独立审阅后逐平台签署。 | 未通过的能力标为未测/失败，限缩运行范围；不发布“无人值守”或持续可用承诺。 |
| 8. 容量扩展决策 | 用现场负载剖析先确定瓶颈在屏幕源、检测、ROI/VLM、录像、磁盘或时钟同步；复测预算和总拥有成本。 | 同输入、同模型、固定负载对照并提供峰值资源和长稳证据；目标机器离线准备、启动、恢复可复现。 | 若需更强硬件，重新制定预算；约一万元基线不成为硬件上限承诺或采购订单。 |

开发时应先把 CU 的数据合同做好，再讨论接入代码。入队时冻结来源、相机、单调采集时间、`view_epoch`、网格/细节模式、layout fingerprint、ROI/坐标变换和原帧标识；出队时不能按可变的当前界面状态重新解释旧帧。切换交叠、超过截止时间、身份或 epoch 不符的帧标为未知。网格/详情单独标定 ROI 与质量门槛；切镜头后重置逐路跟踪、规则基线和复核序列。每路源帧 heartbeat 独立于检测器和 VLM，模型进程健康不能替代画面新鲜度。

新加入的 `SceneChangeWatch`、`InspectionPlanner`、`inspection_profile` 和 `view_feasibility` 属隔离实验模块，没有接入 production runtime，也没有证明实际 UI 或现场效果。应用配置上限仍为 10 路；16 路只是巡视模块的实验设计。不得将实验 API 或实验结果写成已交付运行功能。详见[主动观察架构](../implementation/docs/ACTIVE_OBSERVATION_ARCHITECTURE_20260925_zh.md)和[核验记录](../implementation/docs/ACTIVE_OBSERVATION_VERIFICATION_20260925_zh.md)。

## 画面、盲时与硬件预算

单屏逐路放大受物理时间限制。当前规划预算为每小时最多 180 秒总览不可见时间；按每次离开总览（打开、等待、详情、返回）共 6 秒、恢复总览停留 1 秒估算，连续轮询的名义周期为9路63秒、16路112秒，但会违反每小时180秒预算；保留预算后，长期平均单轮下界约为9路18分钟、16路32分钟，不是最坏延迟保证。这只是规划算术，没有窗口边框、弹窗、切换失败或现场测量；**不能把单屏串行巡视称为连续十路观察**。超过可观测预算时必须记每路 blind 区间并让候选状态未知。持续总览加独立细节窗口/授权码流更适合作为目标架构，但遮挡、最小化、主辅流关联与源像素增益仍要现场验证。

RTX 4060 8 GB、整机约人民币 1 万元是**设计基线**，不是当前采购报价、已核验市场价格、产品推荐或十路性能承诺。Windows、驱动、模型权重、分辨率、帧率和本机同时录像会改变资源需求。只有目标机器的 GPU/VRAM/CPU/RAM/磁盘时序、实测误差和维护成本齐全后才可决定购买。

中国无 VPN 的运行设计应把模型权重、安装包、依赖和校验清单预置在本地，生产运行不依赖外网拉取模型或上传摄像画面；这只是可行的离线准备路径。当前没有目标现场网络、驱动安装、模型启动和十路运行的验收证据。离线准备、可启动、可获取模型和现场稳定是四个不同状态。

## VLM、异构 PD 与扩容准入

先建立单 GPU/单实例的受控基线：每路最多保留一个最新待处理候选，旧候选被合并/替换时计数；已开始的请求不得静默丢弃；请求使用硬截止和幂等 ID，失败隔离到人工复核。固定 ROI 来源、裁剪变换、像素预算、帧数量、模型版本和提示词，再分别评估容量与语义。画面放大不会恢复源图未保留的像素。

只有以下条件同时具备，才进入 Prefill/Decode 分离（PD）实验：

1. 对目标模型和实际 ROI 请求有重复的阶段计时，证明确切瓶颈在视觉 Prefill 或 Decode，而不是采集、排队、证据写入、错误负例或源画质。
2. 有一台与目标运行时兼容的第二计算设备，并完成显存、网络/IPC、模型副本、驱动和离线依赖核验。单 RTX 4060 不会因把阶段拆名而产生额外 GPU 算力。
3. 在相同模型、权重 digest、ROI 字节、预处理、截止时间和十候选顺序下，对照单实例与 PD；至少测 p95、超时/删失数、准确度、峰值显存、断连/重启、KV 交接失败、重复提交和恢复行为。
4. 准入结果由独立审阅者确认满足原 15 秒 SLA 和视觉任务门槛。吞吐变快不能抵消误报，结构化输出合法也不是语义正确。

被评估的异构实验仓库没有可直接部署的推理服务实现，且其报告设备与单 4060 预算不匹配。vLLM/SGLang 的多阶段方案有额外组件和状态交接；尚无该项目目标 Qwen 图像输入及现场恢复的端到端通过证据。现阶段继续先稳定单 GPU、有界队列和可审计失败路径。见[异构 GPU 评估](../implementation/docs/HETEROGENEOUS_STABILITY_20260925_zh.md)。

对外可用的窄表述是：“在已标定的来源和视角中，系统提示可见变化并提供证据和不确定性，由人复核。”只有经独立现场 Gate 覆盖的任务、平台、路数、时段和输入质量，才可进一步描述其能力。
