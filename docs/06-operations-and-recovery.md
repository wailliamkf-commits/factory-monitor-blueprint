# 运维与故障恢复手册

本手册用于未来的现场运行和证据保全。当前系统不是已验收的无人值守服务。操作者应能看到每路是否新鲜、是否映射有效、是否正在录像、模型是否超时，以及停止是否排空；未提供的状态必须记录为未知，不能用默认值伪造健康。

## 可用状态与未交付的运维量

| 领域 | 当前源码中已有的局部能力 | 仍待实现或待现场证明 |
| --- | --- | --- |
| 运行状态 | 控制器 `status()`；事件状态 candidate/recording/complete/incomplete/error；复核 pending/supported/dismissed/uncertain/timeout/error；运行时可发出部分逐路 health 消息；保存 SQLite 事件、证据路径、缺口和复核结果。 | 统一的无人值守健康面板、跨进程状态汇总、操作员确认回执、健康历史和现场可读的恢复报告。状态消息不等于端到端健康。 |
| 源画面新鲜度 | 有逐路 heartbeat 检查接口；可按校准 ROI 判断最近是否变化；旧帧/不可观测状态能在局部运行逻辑中产生健康原因。 | 十路真实客户端的 heartbeat ROI 校准、静止场景误判与动态场景验证、各 OS/客户端长测、每路覆盖率闭环。没有有效 heartbeat 时要标 `UNKNOWN`。 |
| 证据与队列 | 证据、预览、SQLite/WAL；有界的若干内部队列；十路合成 smoke 写终态报告；模型请求有 15 秒截止并可记 timeout。 | 全链路统一队列账（attempted/accepted/rejected/evicted/consumed/remaining/shutdown-discarded）、丢失区间核对、磁盘预警、保留账本、可审计的全量逐帧完整性。不得把旧累计值 81 称作精确丢帧数。 |
| 停止与恢复 | 控制器可请求停止、等待部分 worker、持久化事件；软件烟测观察中断事件在重启后标成 incomplete。 | 目标 Windows/Mac 实际关停、所有 worker 自然退出、最终队列对账、磁盘满/系统重启/子进程卡死恢复与恢复结果核验。当前没有已验证的永久看门狗或受限自动重启闭环。 |
| 客户端控制 | 当前人工操作客户端；校准与视图规划有隔离实验逻辑。 | 自动 OS 点击未交付/未解禁；实际客户端布局变化、坐标错绑或弹窗时的冻结、自动返回总览、每个动作的 UI 和新帧回执都待实现/验收。 |

事件上的 `recording_status=complete` 仅表示封装结束。只有媒体全帧可解码、时间戳/时长/缺口经独立检查后，才可记录完整证据。录像不完整、数据缺失或数据库处于写入中均须保留明确缺口。

## 每次运行开始前

1. 建立唯一 `run_id` 和仓库外的新证据目录；预先记录开始指令、操作者、运行模式、机器/OS build、客户端版本、源码提交/工作树、实际配置 SHA-256、模型 digest、依赖版本、GPU/驱动、时区与时钟对齐方法。现场路径、账号、密钥只保留在获授权的本机记录，不写入模板或 Git。
2. 核实十路映射、布局、缩放、网格/细节 ROI、相机 ID、时间戳、heartbeat ROI 和预期可观察时段；任何一项无法读回都标未知，先不要扩大运行范围。
3. 检查数据盘剩余空间、文件系统、证据保留余量、数据库及 WAL/SHM 是否被旧进程持有；一个 SQLite 数据库只允许一个运行实例写入。
4. 确认云端图像复核关闭、生产点击关闭；模型仅使用获准的本机 loopback 服务。中国大陆无 VPN 运行必须依赖事先校验的离线模型、安装介质和依赖包；离线准备可行不等于目标现场网络、驱动或启动已验证。
5. 先做单路、短时且被动的准备，再按[验证阶段门槛](05-validation-and-acceptance.md)逐级放行。

项目初始化和启动命令仅针对冻结实现，不代表蓝图仓库有运行服务。先在空的新版本目录中准备实现所需环境，再按[稳定运行手册](../implementation/docs/STABLE_OPERATION_zh.md)执行经审阅的命令；不要覆盖在运行目录或有未核对补丁的现场目录。

## 故障处理路径

| 故障 | 立即动作 | 证据和恢复条件 | 当前自动化状态 |
| --- | --- | --- | --- |
| 源画面断流、冻结、黑屏、遮挡 | 将受影响路标为不可观察/未知，停止将“无检测”解释为无事件；人工确认客户端和采集状态。不要重置时间后把缺口抹掉。 | 记录最后新鲜帧、恢复后首帧、单调时钟、相机映射、heartbeat ROI、开始/结束缺口、原因标签、客户端界面状态及人工动作。只有新鲜画面和身份读回通过，才恢复该路观察。 | 局部 heartbeat/health 判定存在；断流检测准确率和目标现场恢复未验。统一告警/自动重连未交付。 |
| 磁盘空间不足或写入失败 | 停止接收新候选/人工停止运行，避免继续扩大写入；不要删除正在写的数据库、WAL/SHM 或在途媒体。必要时切换到预先核验的空白盘目录并新建运行 ID。 | 保存 OS 磁盘快照、错误日志、DB/WAL/SHM、在途事件 ID、最后成功写入和缺口；空间恢复后先隔离并只读核验数据库/媒体，再决定重开。清理必须由获授权操作者按已审计保留策略执行。 | 没有已验证的磁盘阈值告警、容量预留和自动安全清理。配置的事件保留数不能替代磁盘压力测试。 |
| 本地模型超时、服务退出、JSON/语义异常 | 保留候选和证据，显示“模型超时/异常、需人工复核”；模型不得将其改成正常。不要为了通过而提高 SLA、缩小分母、静默重试或启动第二个未测服务实例。 | 记录候选发生到终态的完整含队列时延、请求 ID、模型 tag/digest、输入帧时间戳/哈希、超时/错误、队列龄、服务进程和人工结论。恢复后先用被批准的固定样本验证服务可用，旧事件不覆写。 | 有 15 秒 request/deadline 和 timeout/error 状态；并发 Qwen 当前 2/10 完成、8/10 超时且完成结果误报公交负例，语义与容量均未解决。 |
| OOM、GPU/驱动重置或资源骤升 | 停止新增模型任务并由操作者请求干净停止；保留捕获/录像输出。若无法清楚确认进程状态，按强制终止记录，不声称排空。 | 保存系统事件、GPU/CPU/RAM/磁盘原始时序、进程树、模型日志、最后请求和退出码；排查后以新运行目录重启，先做固定小负载并检查输出一致性。 | OOM隔离、显存阈值、受限模型重启和恢复核验尚未被目标设备证明。 |
| UI 布局变化、焦点丢失、缩放/DPI、弹窗、错镜头 | 若自动控制将来启用，立即冻结点击；当前由人停止对错误画面的判断，手动恢复获准布局。错绑镜头的结果都作为未知并保留。 | 记录客户端版本、窗口尺寸/DPI、布局指纹、请求 ID、预期/实际相机 ID、frame epoch/时间戳、UI 事件和恢复读回。需重新校准并通过循环验证后方可继续。 | 本项目当前自动点击关闭。校准器/规划器属于隔离模块；没有生产运行时自动控制或真实 UI 读回。 |
| 应用崩溃、冻结、强制结束或主机重启 | 记录停止/崩溃发现时间，不要覆盖原目录；确认相关子进程是否仍存活，再决定是否关停。数据库仍写入时不复制主 DB 当作一致备份。 | 保存原始 stdout/stderr、应用日志、进程树/退出码、事件 DB 与 WAL/SHM、未封装媒体、源码/配置/模型身份；恢复后核对旧事件是否标 incomplete/gap、队列终态和残留子进程。 | 合成 restart smoke 覆盖有限中断；真实 OS 故障下的一致恢复尚未验证。 |
| 更新后无法启动或行为退化 | 停止新版本并保留现场副本；将旧版本、配置、数据库和证据副本隔离。只在经过版本相容审查的副本上恢复上一版本。 | 比较提交/包 SHA-256、未提交差异、schema、依赖、模型和数据目录；失败版本产生的新记录不可由旧 DB 覆盖。迁移须另有备份与审阅。 | 自动更新/回滚、跨版本迁移尚未交付。 |

## 停止、证据收集与回退顺序

停止接收新工作，记录停止理由和请求时间；让采集、录像、复核和数据库写入完成排空，逐 worker 记录退出/超时、进程退出码和残留进程。若须强制结束，记录为 `forced_termination=true`，队列/媒体一致性记未知，Gate 失败。停止后再做一致性备份；运行中的 SQLite 应连同 WAL/SHM 用验证过的一致备份方式保存，不能只拷主库。

每个 `run_id` 的本机证据至少应包含：完整 stdout/stderr 和应用日志、源码提交和工作树状态、配置/模型/依赖身份、事件数据库及 WAL/SHM、媒体/预览/manifest、逐帧解码结果、磁盘和资源时序、客户端身份/布局读回、缺口账、复核及人工标签、停止原因/worker 退出/恢复结果。对每个文件生成 SHA-256 清单；同时记录证据保管人和访问权限。只提交合成或充分脱敏的材料，不把现场视频、客户身份、账号、密钥或私人日志推入 GitHub。

更新应在维护窗口执行：保留旧版完整副本；把新源码放入新版本目录；新建隔离环境、模型和输出目录；先只读预检，再重复对应阶段的低风险验证。失败回滚只切回经验证的旧版本及其匹配数据副本。新版本的数据先隔离导出和审查，不覆盖旧数据库。

参照[稳定运行与版本交付](../implementation/docs/STABLE_OPERATION_zh.md)、[实现接口状态](../implementation/docs/INTERFACES.md)和[验收协议](../implementation/docs/ACCEPTANCE.md)。
